CRITICAL
🔴 Admin Client Falls Back to ANON_KEY

File: lib/supabase/admin.ts (Lines 22-23)

Problem: If SUPABASE_SERVICE_ROLE_KEY is missing, the admin client silently falls back to NEXT_PUBLIC_SUPABASE_ANON_KEY. This bypasses Row-Level Security (RLS) checks intended to protect user data.

const serviceKey =
  process.env.SUPABASE_SERVICE_ROLE_KEY ||
  process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY; // ← FALLBACK TO ANON KEY

Impact: Data leaks, unauthorized access, financial records exposed

Action: Make SERVICE_ROLE_KEY mandatory; throw error if missing

🔴 Guest Order Response Data Duplication

File: app/api/guest/order/route.ts (Line 29)

Code: { ...result, data: result }

Problem: Response wrapping duplicates entire result object. Causes:

  • Excessive payload sizes
  • UI confusion mapping nested data
  • Potential out-of-sync data fields

Expected: { success: true, data: result }

Impact: Network bandwidth waste, frontend parsing errors

HIGH
⚠️ In-Memory Rate Limiter Not Distributed

File: lib/middleware/rate-limiter.ts (Lines 20-34)

Problem: Rate limiting uses in-memory store when Redis unavailable. On multi-instance deployments, each instance has its own store = rate limits are inconsistent across instances.

Current Limits:

  • PIN Failures: 5 per 15 minutes per IP/business
  • Guest Orders: 15 per minute per IP/table

Impact: Users can bypass rate limits by round-robin load balancing across instances

Capacity: Single instance can handle ~1000 concurrent connections; scales linearly with instances

MEDIUM
⚠️ External Pincode API Dependency

File: app/onboarding/host/page.tsx (Line 79)

Problem: Pincode validation calls external API: api.postalpincode.in

Risks:

  • Network latency on form submit
  • Third-party API downtime blocks onboarding
  • No fallback validation
  • CORS issues on mobile

Action: Cache results locally; implement fallback validation
